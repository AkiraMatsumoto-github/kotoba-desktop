# kotoba-desktop 開発計画

[設計書](design.md) の第 3 章（要件）、第 10 章（検証計画）、第 11 章（ロードマップ）を作業単位に分け、進捗をこのファイルで管理する。

## 進め方

- 作業が終わったらチェックボックスを `[x]` にし、下の「現在地」と各フェーズの状態を更新する。コミットにはタスク ID（例: `P1-07`）を書く。
- 計測値や判断の根拠は、該当タスクの下に 1 行で残す（例: `→ 中央値 0.52 秒（10 回）`）。
- 設計を変えたときは設計書を直し、「決定事項」に日付と理由を 1 行で残す。
- 関門（G0 / G1）に合格するまで次のフェーズには進まない。ただし Phase 1 の実装は、Phase 0 の人の手による検証を待つ間に前倒しで進めた（決定事項を参照）。

- [x] **P0-05** 項目 3 VRAM: 常駐中と認識中を nvidia-smi で確認。合格は 3 GB 以内

- [x] **P0-06** 項目 4 句読点: v2.0 の出力に「、。」が付くかを記録し、`punctuation` の既定値を決める

## Phase 1: MVP

機能要件 F1〜F6 を作る。Win32 の呼び出しは `win32/` に閉じ込め、それ以外は GPU なしで単体テストできるようにする。チェックは実装と自動テストが済んだもの。実機での使い勝手は G1 の常用で確かめる。

### 土台

- [x] **P1-01** 設定（`config.py`）: pydantic のスキーマ、`%APPDATA%\kotoba-desktop\config.toml` の読み込み、無ければ既定値で作成、誤りはどの項目かを返す
  → トレイから値を書き換える `update_value`（コメントを残して 1 行だけ書き換える）も追加
- [x] **P1-02** Win32 ラッパー（`win32/`）: `input.py`（SendInput）、`clipboard.py`（退避・復元・更新番号・履歴除外形式）、`ime.py`、`window.py`（前面プロセス名・クラス名・昇格の判定）

## 決定事項

| 日付 | 内容 | 理由 |
| --- | --- | --- |
| 2026-10-16 | ショートカットキーの既定を Ctrl+H にする | 使いやすさを優先。各アプリの Ctrl+H は使えなくなるため、困れば設定で変える |
| 2026-10-16 | 長い発話は VAD で 15 秒以内に区切って認識する（`audio.max_chunk_s`） | 23 秒の発話を 1 回で認識すると最後の文が抜けた（P0-04） |
| 2026-10-16 | 無音・雑音の除外は VAD に任せる | 無音でも `no_speech_prob` が 0.1 程度で、しきい値では除外できない（P0-07） |
| 2026-10-16 | マイクの準備ができてから「聞き取り中…」を出し、`audio.keep_open` を設定で選べるようにする | 手元のマイクは開いてから音が届くまで約 460 ms かかる（P0-12） |
| 2026-10-16 | 後処理は前面ウィンドウのプロファイルを決めてからかける（設計書第 8 章の手順 1 と 3 の順を入れ替え） | 句読点の扱いをプロファイルごとに上書きできるようにするため |
| 2026-10-16 | よく変える項目は設定画面で変え、設定ファイルを開かせない。保存はファイルを丸ごと書き出す | 設定ファイルを直接開かせたくないという要望。全項目を画面にするのではなく、変える見込みのある項目だけにした。手で編集する前提がなくなったので、コメントを残す 1 行書き換えはやめた |
| 2026-10-16 | ショートカットキーを設定画面で選べるようにし、Win キーの組み合わせも許可する | Windows 標準の音声入力（Win+H）に合わせたいという要望。Win+H 自体は Windows が登録済みで使えないので、登録できる組み合わせ（Win+Alt+H など）を選べるようにした |
| 2026-10-16 | 打鍵方式の検証（P0-10）を取り下げ、P2-04 は必要になったら着手する | 貼り付け方式で全入力先が合格した。打鍵方式は貼り付けが効かないアプリ向けの予備で、そうしたアプリはまだ無い |
| 2026-10-16 | `audio.keep_open` は既定でオフのままにする | P0-12 で、押してすぐ話しても最初の音が欠けなかった |
| 2026-10-16 | Phase 0 の入力検証は本番のモジュールを使い、Phase 1 の実装を前倒しする | 人の手による検証を待つ間に進めるため。PoC 専用のコードを作らないことで、検証したコードがそのまま本番で動く。G0 で問題が出たら入力部分を直す |
